# cPanel Deployment Guide for Fradynex

This project is fully configured, optimized, and ready for deployment on **cPanel** hosting.

There are **two supported deployment methods** depending on your cPanel hosting setup:
- **Method 1 (Recommended): Standard Web Hosting / Static SPA via `public_html`** (Fastest, zero server maintenance, uses Apache/LiteSpeed with our pre-configured `.htaccess`).
- **Method 2: Node.js Application via cPanel "Setup Node.js App"** (CloudLinux / Phusion Passenger running `server.js` / `app.js`).
- **Bonus Method 3: Automated Git Deployment using `.cpanel.yml`**.

---

## Method 1: Deploying via cPanel File Manager (Standard / Recommended)

This is the standard and most reliable method on shared and dedicated cPanel servers. The application is pre-compiled into the `dist/` folder with complete client-side routing, caching, and compression configured.

### Step 1: Ensure the Latest Production Build is Ready
If you make code changes, run:
```bash
npm run build
```
This generates the optimized production bundle inside the `dist/` folder. All assets, `.htaccess`, `robots.txt`, and `sitemap.xml` are bundled automatically.

### Step 2: Enable "Show Hidden Files" in cPanel
1. Log in to your **cPanel** dashboard.
2. Open **File Manager** (under *Files* section).
3. Click the **Settings** gear icon in the top-right corner.
4. Check **Show Hidden Files (dotfiles)** and click **Save**.
   *(This ensures that `.htaccess` is visible and uploaded properly).*

### Step 3: Upload Files to `public_html`
1. In File Manager, navigate to `public_html` (or your subdomain's document root, e.g., `public_html/subdomain`).
2. If there are default placeholder files (like `default.html` or `index.php`), remove or backup them.
3. Upload all the contents inside the `dist/` directory into `public_html`:
   - `assets/` (folder containing JS, CSS, and vendor chunks)
   - `index.html`
   - `.htaccess` *(Critical: handles React Router SPA navigation and caching)*
   - `robots.txt`
   - `sitemap.xml`
   - `_redirects`
4. Alternatively, you can zip the contents of `dist/`, upload `dist.zip` to `public_html`, and click **Extract**.

### Step 4: Verify Your Website
- Visit your domain (e.g., `https://fradynex.com`).
- Test internal routes such as `https://fradynex.com/about`, `https://fradynex.com/services`, `https://fradynex.com/portfolio`, `https://fradynex.com/blog`, `https://fradynex.com/contact`.
- Refreshing the browser on any internal route will continue to work seamlessly thanks to the pre-configured `.htaccess` rules.

## Method 2: Deploying via cPanel "Setup Node.js App"

If your cPanel provider includes CloudLinux Node.js selector (Phusion Passenger):

### Step 1: Create the Node.js Application in cPanel
1. In cPanel, find and click **Setup Node.js App** (or *Node.js Selector*).
2. Click **Create Application**.
3. Fill in the fields:
   - **Node.js version**: Choose `20.x` or `18.x` (LTS recommended).
   - **Application mode**: `Production`.
   - **Application root**: Path to your application folder (e.g., `fradynex-app` or `public_html`).
   - **Application URL**: Select your domain or subdomain.
   - **Application startup file**: Enter `app.js` or `server.js` (both are provided in the project root).
4. Click **Create**.

### Step 2: Upload Project Files
Upload the project files to your Application root folder:
- `dist/` *(generated by `npm run build`)*
- `server.js` & `app.js`
- `package.json`
- `.htaccess`

### Step 3: Install Production Dependencies
1. In the cPanel Node.js App panel, click **Run NPM Install** (or access terminal and run `npm install --production`).
2. Click **Restart** on your Node.js application.
3. Access `https://yourdomain.com/health` to verify server health (`{"status":"ok"}`).

## Method 3: Automated Deployment via cPanel Git Version Control

If you use cPanel's built-in **Git Version Control**:
1. Push this repository to GitHub/GitLab or clone directly in cPanel.
2. In cPanel -> **Git Version Control** -> Manage -> **Pull or Deploy**.
3. The included `.cpanel.yml` file will automatically copy the `dist/` files and `.htaccess` into `public_html/`.

## Summary of Included Production Configurations

| File | Purpose |
|---|---|
| `public/.htaccess` / `dist/.htaccess` | Apache rewrite rules for React Router (preventing 404s on refresh), GZIP compression, MIME types for JS/CSS/Fonts, security headers (nosniff, SAMEORIGIN), and browser caching rules. |
| `vite.config.ts` | Code-splitting setup separating `vendor-react`, `vendor-motion`, and `vendor-icons` to minimize initial load time. |
| `server.js` & `app.js` | Express static file server ready for cPanel Phusion Passenger Node.js environments. |
| `.cpanel.yml` | Deployment automation script for cPanel Git Version Control. |
| `robots.txt` & `sitemap.xml` | Search engine indexing and sitemap declaration. |
| `.env.example` | Environment variable definitions for production and API configurations. |

## Troubleshooting Common cPanel Issues

1. **404 Not Found on Page Refresh (`/about`, `/services`, etc.)**
   - **Cause**: `.htaccess` was not copied or is hidden.
   - **Solution**: Make sure "Show Hidden Files (dotfiles)" is enabled in cPanel File Manager, and verify that `.htaccess` exists directly inside `public_html/`.

2. **JavaScript MIME Type Error (`Failed to load module script`)**
   - **Cause**: Apache server not configured with modern MIME types for `.js` and `.mjs`.
   - **Solution**: The included `.htaccess` contains `AddType application/javascript js mjs` which automatically resolves this.

3. **Changes Not Showing After Re-uploading**
   - **Cause**: Browser cache holding old assets.
   - **Solution**: The `.htaccess` explicitly instructs browsers not to cache `index.html` while caching immutable versioned assets. Clear browser cache or hard-refresh (`Ctrl + F5` or `Cmd + Shift + R`).
